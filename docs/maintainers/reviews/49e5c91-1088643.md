# Pre-deployment review: 49e5c91..1088643

Reviewed the complete range containing PRs #18, #24, #26, #6, #29, #28 and #30
against PLAN.md and AGENTS.md. No review skill, delegated reviewer, production
access, deployment or GitHub mutation was used. The findings below are fixed in
the accompanying working-tree changes. Each finding was reproduced with a
failing regression before its fix.

## Findings and fixes

1. **P1 — Forgotten-worktree deletion escapes through an intermediate symlink.**
   `Worktrees.managed_path?/1` accepted `root/link/victim` when `link` pointed
   outside the root. `File.rm_rf/1` then deleted the external victim. Accept only
   normalized absolute direct children, reject child symlinks, and use the
   standard library's descriptor-based deletion to resist symlink replacement
   during recursion. Missing or unsafe roots fail the guard. Managed worktree
   generation already uses this direct-child layout.

2. **P1 — Reconciler-recorded heads bypass retained-repair verification.**
   Status reconciliation updates `remote_head_sha` even for an unrelated merge.
   Postflight then saw that same remote head and skipped verification; the new
   settled-publication fallback returned success. Compare unchanged work to the
   action's frozen preflight head, independently verify changed retained work,
   and require the intended head for all fresh repairs (including managed PRs).
   The settled fallback also checks the observed head, PR URL and base target.
   Success proves the authorized result, not which GitHub actor clicked merge.

3. **P1 — Health snapshots disclose private or agent-controlled text.**
   Raw exception lines can include SQL parameters, credentials, private model
   output or attacker-supplied instructions. Status text, names and labels have
   the same problem. Export identifiers, states, timings and log counts instead.
   Read the journal once, cap it, and keep the raw staging file private.

4. **P1 — An output symlink redirects the root snapshot publisher.**
   The deployed output directory is group-writable and sticky, so an agent can
   precreate the output name before the first snapshot. `mv` follows a symlink
   to a directory. Use atomic `os.replace` instead; it replaces the link itself.
   Exclusive private staging also eliminates the predictable temporary-name
   symlink vulnerability.

5. **P2 — Journal read failures publish an apparently healthy snapshot.**
   A successful preflight did not establish that subsequent reads succeeded;
   `journalctl ... || true` converted failures to empty logs. Check the actual
   bounded read and preserve the previous snapshot on failure. Consumers must
   reject stale `captured_at` values, as documented.

6. **P2 — Busy writes are misclassified as terminal repair/gate failures.**
   Repair postflight converted `:database_busy` to `:terminal_error`; publisher
   gate persistence classified it as a failed gate and blocked publication.
   Keep both retryable, avoid moving worktrees to attention for contention,
   and do not consume publication attempts for busy gate persistence. A real
   independent SQLite writer reproduces the postflight failure and verifies
   that retry completes the transition after lock release.

7. **P2 — Valid TOML spellings produce duplicate managed keys/tables.**
   `[ notice ]`, quoted `notice` headers, and quoted managed keys escaped the
   line matching. Recognize these spellings, keep arm/disarm idempotent, and
   reject duplicate or inline/dotted notice definitions before replacing the
   file. Preserve unrelated notice settings.

8. **P2 — Explicit CLI models disagree with the saved resume model.**
   `--model value` selected one model at start while `AgentProfiles.model/1`
   returned the default for arming. `--model=value` also acquired a second model
   argument. Resolve the explicit argument in one place for start and resume.

9. **P1 — The new source fetch creates a stale-approval dispatch window.**
   Dispatch read the issue, then performed a potentially slow remote fetch,
   then leased against the earlier issue. A regression edits the issue during
   the refresh and demonstrates dispatch on a stale approval. Fetch first,
   perform the final issue read immediately before leasing, and start the lease
   clock after those reads.

## Transaction assessment

The changed publication transactions contain database work, with notification
outside the transaction. No external process/network call or new lock-order
cycle was found in them. The batch external-PR import holds the writer lock for
its whole database batch; concurrent writers contend, rather than forming a
new application-lock cycle.

Immediate transactions can block synchronous button handlers while obtaining
SQLite's writer lock. The installed adapter's default busy timeout is 2,000 ms;
this review does not increase it. A database-busy return is an unsuccessful
transaction, not a completed state transition. Publication reconciler and
publisher errors remain visible/retryable; the two terminal classifications
above needed correction. Deployment launch defers without changing its queued
state on contention. Other reviewed helper callers propagate their errors.

## Boundaries

The filesystem root remains trusted configuration. Permission and existence
checks cannot identify an administrator replacing a root with another directory
of identical ownership/mode, or an unmount leaving an indistinguishable healthy
mountpoint. This change adds no automatic discovery of old or relocated roots.

The shell regressions use executable fakes for privileged services. They do not
assert that the live host's ownership, timer, mounts, Python or sudo setup has
been inspected. Production was not contacted. The full root-owned deployment
boundary must still match the documented configuration.
