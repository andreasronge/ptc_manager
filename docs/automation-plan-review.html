The product promise

The interface should hide orchestration complexity without hiding what agents are allowed to do.

“I choose the work. PtcManager queues it, gives it to a suitable agent, and shows me the result.”

You approve implementation and merging. Routine investigation, scheduling, status tracking, and cleanup happen around those decisions.

Who owns what?

1
You

Priorities, approvals, prompt configuration, and final decisions.

2
PtcManager

Durable queue, schedules, locks, agent choice, audit trail, and presentation.

3
Herdr

Starts the chosen agent and retains its terminal session and output.

4
GitHub

Authoritative issues, pull requests, checks, labels, and merge state.

One flow, many kinds of work

A manual button and a nightly schedule use the same visible, auditable path.

STEP 01

Trigger

You press a contextual button, choose Run now, or a schedule becomes due.

STEP 02

Snapshot

PtcManager freezes the repository, target, prompt version, permissions, and source SHA.

STEP 03

Queue

The work waits safely for the right lane, repository lock, and agent capacity.

STEP 04

Prepare & run

PtcManager verifies and bootstraps the exact workspace first; only then does Herdr start or resume the selected agent.

STEP 05

Reconcile

The UI explains the outcome while GitHub remains the source of truth.

  • If a decision is needed, the UI offers concrete choices and examples.

How this can be completed

Deliver in usable slices. Do not wait for the entire generic system before validating it with real work.

PHASE 01

Make two repositories safe

Repository paths, checked-in gates, authentication health, and source snapshots.

  • Dedicated PtcManager checkout
  • Exact-SHA gate evidence
  • Repository selector
PHASE 02

Make actions configurable

Persisted definitions, visible prompts, prepared workspaces, generic results, and agent profiles.

  • Workspace preflight
  • Capability router
  • Light/heavy capacity
PHASE 03

Generate the experience

Manual triggers produce Planning and Delivery buttons, common results, and run detail.

  • Automations screen
  • Contextual buttons
  • Mobile review flow
PHASE 04

Add durable schedules

Oban Lite stores one future occurrence and survives restarts without duplicate work.

  • Schedule editor
  • Pause and Run now
  • Operations history
PHASE 05

Migrate and prove

Move daily updates through Herdr, add nightly CI, then onboard PtcManager.

  • No direct model launch
  • Real GitHub test
  • One small implementation PR
LATER

Increase autonomy carefully

Event triggers, deploy actions, more agent profiles, and measured routing preferences.

  • Claude read-only pilot
  • Workflow events
  • Deployment lane
